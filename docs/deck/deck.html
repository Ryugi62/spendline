Spendline

Not “an agent that can pay” — a payment that can prove it was allowed.

Spendline is a wallet-and-policy layer for an AI purchasing agent — a person grants a USDT budget with a merchant list and a deadline, the agent (Qwen3-32B on Kiln) proposes purchases, a policy vault on TRON Nile pays only inside that line and records every stop on-chain, and anyone can reconstruct from the receipts alone whether a payment was allowed.

Spendline · 7 / 11

What's new

  • A stop is an event. Refusals are recorded on-chain with the reason, so the history shows what the agent was not allowed to do.
  • Receipts are hash-chained and anchored. Each receipt's hash is an argument of pay(); the vault decides each hash once.
  • The model phrases, the audit decides. Kiln explains a receipt and settles a teammate's question — its words are shown only if they repeat the audit's verdict and use only numbers from the record.

Spendline · 8 / 11

Who pays · where it plugs in

  • Plugs in where an agent would call a wallet: it calls vault.pay(…, receiptHash) instead. The person keeps the owner key; the agent key can only ask.
  • Who needs it: teams that let agents buy compute, credits and API time — and any finance or compliance reader who must check a payment without trusting the operator.
  • Business (hypothesis, not validated): the vault and the audit stay open (Apache-2.0); a hosted audit with alerts on stops is the paid layer.
  • Why TRON · USDT: an agent's budget is money people already hold as a stablecoin; USDT settles as a plain TRC20 transfer inside pay(). The vault is ordinary Solidity on the TVM — nothing in it is specific to one seller or one app.
  • For Kiln: a reference pattern for an agent that spends — every decision through Kiln, tokens and energy reported per flow.

Spendline · 9 / 11

Not done — stated, not hidden

  • Testnet only (TRON Nile, test USDT) — the brief asks for devnet or testnet.
  • One line per vault; a new grant replaces the old one (the audit replays every grant).
  • Signing is on the person's machine (CLI), not in the browser — keys never enter the page.
  • Energy is an estimate from wall time; Kiln exposes no power telemetry.
  • Parts were built before the event window; the README lists every commit, before and during.
